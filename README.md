播放器统一在主页。左上角可以换装扮，歌单里可以整理自己想听的歌；换装扮不会切歌。

原来的思诺、心宜精选与 Live 歌库分别保留为预置歌单。心宜数据文件已移到 `catalogs/`，旧 `/fiona/` 入口由 `404.html` 跳转到主页。

自建歌单、收藏和播放记录保存在当前设备。头像在本机裁剪压缩，使用 IndexedDB 保存，每位最多一张、每张最多 512 KB；原图不上传。桌面图标不随装扮或上传头像改变。

`personal-library.js` 负责歌单存储与旧数据迁移，`library-ui.js` 对接歌单界面和播放范围，`wardrobe.js` 负责装扮与头像。默认成员图来源见 [图像说明](imgs/wardrobe/SOURCES.md)，安卓构建见 [安装包说明](android-app/README.md)。

验证：`node --test tests/*.test.mjs`。

手机播放页频谱由 `mobile-visualizer.js` 绘制：最多 48 根柱子、24 帧、1.5 倍像素密度，安卓使用 512 点 FFT。iOS 保留原生音频链路，使用随播放启停的装饰动画，不代表真实频谱，避免 HLS 在 Web Audio 中缺少样本或影响声音。动画不会额外请求或解码歌曲；暂停、离开播放页、后台和“减少动态效果”均停止绘制。电脑频谱与小窗保留原来的样式。

歌单页直接提供“添加歌曲”和“导入与管理”，设置页只保留偏好。添加歌曲支持 BV 号、完整视频链接及含 b23.tv 短链的整段分享文案，保留 `p` 和时间参数。可单选或批量导入分 P、读取当前 P 的公开章节，或手动填写开始／结束时间（秒数、分:秒或时:分:秒）。章节不可读时不会阻止整段导入；没有公开章节时不推测歌曲边界。文件与公开收藏夹导入集中在管理面板，已导入视频也可通过歌曲菜单选择分 P／章节。

需要同步部署 [完整边缘函数](edge-functions/bilibili.js)：`/info` 增加分 P 列表和短链参数，`/chapters` 通过当前 P 的 CID 读取 `view_points`；标题接口受限时尝试分 P 接口。只跟随 B 站允许域名上的短链跳转。B 站网络限制仍会影响在线读取，可重试或用 BV 号与手动歌名添加。

`playback-chapters.js` 将公开章节按 BV + P 缓存在本机（最多 64 个视频／分 P，持久化总量约 512 KB 上限）；导入和播放共用目录。播放页的“章节”入口显示当前段落，可打开目录直接跳转，不改变播放／暂停状态，也不切成其他歌曲。分 P 目录相互独立，片段只显示范围内的章节并使用相对时间。目录读取失败时可重试，已保存的目录离线仍可用；切歌后丢弃旧请求的界面结果。音频开始播放后才自动补读目录，后台不主动发起章节查询。

原歌曲存储键保留原样；新增分 P／片段使用 `BV…@p2@t20-40` 作为内部独立条目键，界面显示正常分享链接。收藏、待播、歌词、缓存、导入导出和续播均区分这些条目，进度与锁屏定位相对于片段开头。片段使用原音频的指定范围播放，不转码；离线缓存仍保存所在 P 的整段音频，多个片段分别缓存可能占用额外空间。

后台播放使用支持时的 `audioSession.type = playback`；iOS 和后台切歌复用已播放的音频对象，未缓存的下一首跳过不必要的 IndexedDB 等待。缓冲充足时在结束前准备下一首，后台窗口提前至 90 秒；进入后台取消自动下载和批量缓存以优先播放。`waiting`／`stalled` 持续 10 秒且播放位置未前进时，最多尝试两次保留进度重连；用户暂停、切歌、恢复播放或旧请求失效会取消该次恢复。后台调度与系统中断仍受浏览器限制，实际熄屏连续播放需手机验证。

当前头像会生成一张临时方形 JPEG 交给 Media Session，供锁屏、控制中心和灵动岛作为播放封面使用；头像仍保存在本机，手机主屏幕上的安装图标不受影响。

`playback-ui.js` 负责进度条：前台按帧更新，拖动时合并预览、松手只跳转一次，支持触摸、鼠标、键盘和取消手势。缓冲检查与进度保存继续走音频事件；初始音频只绑定一套稳定监听。歌词节点和歌单数据按版本复用，搜索合并到下一帧，弹层遮挡时暂停背景绘制。移动端底栏通过自动外边距居中，避免改变固定歌名的定位参照。

手机开屏由 `home-experience.js` 用最多 900 个粒子聚合当前装扮的名字和副标题，约 2 秒结束，包含聚合、停留和文字淡入；点击后在约 0.15 秒内快进收尾，不阻挡操作。首次加载暂处后台时等待可见，主屏幕应用从后台或页面缓存恢复时，在首页重新播放；工具栏引起的高度变化不会提前结束动画。“减少动态效果”仍跳过。歌曲库读取后同时静默预加载：优先上次播放的歌曲，否则预选一首随机歌曲；首次随机直接复用预选结果，不自动出声，省流量模式下跳过预加载。首页头像在播放时出现轻量扩散光圈和播放标记，暂停、后台、弹窗遮挡时停止动效。

主屏幕版在场景顶部保留一层与页面同色的 16px 固定背景，给 iOS 状态栏提供明确的取色来源，处理关闭直播等弹窗后底色变灰的问题；不占布局、不拦截点击，浏览器版隐藏。厚度需大于 WebKit 边缘取色时忽略的 10px 边框阈值，主题色、启动背景与页面背景也保持一致。原生状态栏效果仍需 iPhone 实机验证。

首页的直播电台由 `live-radio.js` 管理，显示五位成员的真实开播状态（轮播不算直播），约 90 秒刷新一次，后台暂停查询；状态未知时仍可选择成员尝试收听。胶囊区分未开播、单人／多人开播、连接中、收听中、暂停和连接失败。直播与歌曲互斥，保留歌曲进度，支持重试、关闭、返回歌曲和前往 B 站直播间。

需要同步替换 [完整边缘函数](edge-functions/bilibili.js)：新增 `/live/status`、`/live/stream`、`/live/playlist.m3u8`、`/live/segment.aac`。函数仅支持五位固定成员，限制直播 CDN 地址并校验重定向。解析时同时检查主、备用 CDN 的播放列表与真实音轨，选用可连通的 TS 或 fMP4 线路；fMP4 只提取 AAC-LC 音轨，移除视频数据并补上 ADTS 和 ID3 时间戳。手机只收到音频，无需转码；上游仍含视频，边缘函数会产生相应流量与分片请求。读取兼容 EdgeOne 的 ArrayBuffer、ArrayBufferView 和文本分块，返回二进制时使用 ArrayBuffer。网页在暂停歌曲前先验证直播播放列表，失败时显示接口返回的原因。iPhone 使用原生 HLS，缺少原生 HLS 的浏览器在首次收听时加载本地 HLS.js，版本及许可证见 [vendor 说明](vendor/README.md)。未更新函数时会给出提示，原有歌曲播放不受影响。
